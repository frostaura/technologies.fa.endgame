# Building on the app kit

Every app is one .NET 10 API (EF Core + PostgreSQL) that serves its own React front end, built on the
app kit. Read `AGENTS.md` at the repository root first; it is the app's own instructions and wins over
this skill where they differ.

## Where things go

- `api/Program.cs` — start-up: `AddEndgameApp<AppDb>()`, `UseEndgameApp()`, then one `api.MapX()` per feature. Keep it short.
- `api/<Feature>/` — one folder per feature: the entity (`Thing.cs`) and its endpoints (`ThingsEndpoints.cs`).
- `api/Data/AppDb.cs` — the `DbContext`, one `DbSet` per entity.
- `api/Migrations/` — generated by `make migration`; never edited by hand.
- `api.tests/` — xUnit against the real app (`EndgameAppFactory<Program>`).
- `web/src/<feature>/` — pages and their tests; `types.ts` mirrors the API's records.
- `web/src/App.tsx` — routes; pages other than the first are `lazy()`.
- `docs/` — what the app is; say what changed.
- `vendor/` — the kit's packages. Never edit them.

## The five rules

1. No URL starts with `/`: call `api("things")`, link with `<Link to="/things">`, write assets as `./logo.svg`.
2. Every endpoint is on the `api` group with `.WithName("verbNoun")` and `.WithDescription("…")`.
3. No secret, key or connection string in code or config; models through `IEndgameModels`, secrets through `IEndgameSecrets`.
4. Every schema change is a migration (`make migration name=AddThing`); never edit a committed one.
5. Every read shows loading, failed, empty and loaded differently (`useApiQuery` with `LoadingState`, `FailedState`, `EmptyState`).

Every screen carries the kit's test ids (`page-<view>`, `<entity>-item`, `new-<entity>`, `save-<entity>`, …): the
table is in `AGENTS.md` and the `write-a-screen` skill, the plan item names the ones its screens carry, and the
factory checks each exists in `web/src` as `data-testid="…"`.

## Proving a change

`make lint` and `make test` must pass with zero warnings. A change is done when there is a test for the
behaviour on each side it touches, a navigation test (`renderApp(<App />, { at: "/" })`, then click) for each link
or button that moves between pages, and `docs/` says what changed. Commit each finished feature on its
own with `commit`, then update `PROGRESS.md`.
