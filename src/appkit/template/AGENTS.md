# AGENTS.md — how this app is built

One Endgame app: a .NET 10 API (EF Core + PostgreSQL) that serves its own React front end, as one
container. The platform runs it, gives it a database, and provides identity, models, secrets,
email, schedules, webhooks and telemetry through the app kit (`Endgame.AppKit`, `@endgame/appkit`).
The example feature is **Notes**; replace it with the real product, keeping its shape.

## Where things go

| Path | What |
| --- | --- |
| `api/Program.cs` | Start-up. `AddEndgameApp<AppDb>()`, `UseEndgameApp()`, then `api.MapX()` per feature. Keep it short. |
| `api/<Feature>/` | One folder per feature: the entity (`Note.cs`) and its endpoints (`NotesEndpoints.cs`). |
| `api/Data/AppDb.cs` | The `DbContext`. One `DbSet` per entity. |
| `api/Migrations/` | Generated by `make migration`. Never edited by hand. |
| `api.tests/` | xUnit tests against the real app, its own database and the dev platform (`EndgameAppFactory<Program>`). |
| `web/src/<feature>/` | Pages and their tests. `types.ts` mirrors the API's records. |
| `web/src/App.tsx` | Routes. Pages other than the first are `lazy()`. |
| `docs/` | What the app is and why it is built this way. Keep it current (see `docs/README.md`). |
| `vendor/` | The app kit packages. **Never edit.** The platform upgrades them. |

## The five rules — never break these

1. **No URL starts with `/`.** The app is served under `/<org>/<division>/<project>/` *and* at the
   root of a subdomain from the same build. Call the API with `api("notes")`, link in-app with
   `<Link to="/notes">` (the router adds the base), and write assets as `./logo.svg`. Never change
   `base: "./"` in `vite.config.ts` or the `<base href="/" />` in `index.html`. ESLint
   (`endgame/no-root-relative-url`) fails the build otherwise.
2. **Every endpoint is mapped on the `api` group with `.WithName("verbNoun")` and
   `.WithDescription("…")`.** The platform turns each into an MCP tool; the app refuses to start
   without them, and the error says exactly what to add.
3. **No secret, key or connection string in code or config.** Models go through `IEndgameModels`,
   secrets through `IEndgameSecrets`, the database comes from the environment. Never call a model
   provider or any other host from the browser.
4. **Every schema change is a migration**: `make migration name=AddTagsToNotes`. Never edit a
   migration that has been committed; add another.
5. **Every read shows loading, failed, empty and loaded differently.** Use `useApiQuery` with
   `LoadingState`, `FailedState` and `EmptyState`. A failed read is never shown as "nothing here".

## Conventions

- **Back end:** endpoints return `TypedResults`; errors are problem details
  (`TypedResults.Problem(statusCode: 404, …)`). Request records carry DataAnnotations
  (`[Required]`, `[StringLength]`) — the kit checks them before the handler runs and answers 400
  with field errors. Store `EndgameUser.Id` as an owner, never an email.
- **Signed-in only:** add `.RequireUser()` and take `EndgameUser user`. Browsers are sent to sign
  in; API calls get 401 with `signInUrl`. Take `EndgameUser?` where signing in is optional.
- **Front end:** primitives from `@endgame/appkit/ui`; classes from the token layer only
  (`bg-surface`, `text-ink-muted`, `text-primary`). No hex colours, no `p-[13px]`, no fonts or
  scripts from other hosts. Light, calm, one accent. Use the width on large screens (columns, a
  side panel — never one narrow centred column), and make every page whole on a phone: one column
  under `sm`, nothing wider than the screen, buttons and links at least 44px tall (`min-h-11`),
  labels above fields, the main action full width (`max-sm:w-full`), `pt-safe-t`/`pb-safe-b` where a
  page meets the screen's edge, `min-h-dvh` rather than `min-h-screen`.
- **The app's name** is written once, in `web/src/appName.ts` (and `web/index.html`'s `<title>`). Each
  page names itself with `usePageTitle("All notes")`, which titles the tab "All notes · Notes".
- **Errors in the UI:** `api()` throws `ValidationError` (show `errors` by field),
  `NotSignedInError` (go to `signInUrl`), `NotFoundError`, `BudgetExhaustedError`.
- **Reads stay current by themselves:** after any successful write through `api()` (POST, PUT,
  PATCH, DELETE), every `useApiQuery` on screen re-reads, keeping its data shown meanwhile. Do not
  hand-wire refreshes between pages or lists; write through `api()` and every read follows.
- **The address comes from the router:** `useParams()`, `useSearchParams()`, `useLocation()` —
  never `window.location.search`, `.hash` or `.pathname`, which do not change when a `<Link>`
  moves to a page, so the page is not shown. ESLint (`endgame/no-location-read`) fails the build.
  `location.assign(signInUrl())` to leave the app is fine.
- **Product events:** `IEndgameTelemetry.Track("note.created")` for what matters to the business.
  Health, traffic, errors and latency are recorded without any code.
- **Recurring work:** `app.MapSchedule("nightly-digest", "0 3 * * *", run => …)`.
  **Inbound calls** from devices or services: `app.MapWebhook("name", WebhookVerification.HmacSha256(…), …)`.

## Test ids — every screen carries them

The factory's browser checks drive every app the same way, so every app names its elements the
same way, with `data-testid`. `<entity>` is the singular noun in kebab-case (`note`,
`court-booking`), `<view>` a page's name (`home`, `note`, `new-note`), `<field>` the API field and
`<value>` an enum value, both in kebab-case (`WantToRead` → `want-to-read`).

| Test id | On |
| --- | --- |
| `page-<view>` | each page's root element, in every state; the first page is `page-home` |
| `nav-<view>` | each link (or tab) in the app's navigation to that page |
| `<entity>-list` | the element holding a list of them — also when empty (wrap the empty state) |
| `<entity>-item` | each item of a list, plus `data-id="<the item's id>"` |
| `new-<entity>` | the link or button that opens the form to add one |
| `open-<entity>` | inside an item, the link to its own page |
| `<entity>-<field>` | each form input, with a visible `<label>` and `name="<api field>"` |
| `save-<entity>` | the form's submit button |
| `set-<field>-<value>` | a button that sets one field to one value (`set-status-finished`), on an item or its page |

The Notes example carries all but the last (`page-home`, `note-list`, `note-item`, `open-note`,
`new-note`, `note-title`, `note-body`, `save-note`, `page-note`, `page-new-note`). A test id is
never repeated on one screen. The plan item names the test ids its screens carry; the factory
checks that each one is in `web/src` as `data-testid="…"`. Tests select by them
(`getByTestId("note-item")`), as the template's do.

## Navigation tests — every link between pages has one

A page can render when its address is loaded directly and still not appear when a link routes to
it. `web/src/App.test.tsx` renders the real app with `renderApp(<App />, { at: "/" })` from
`@endgame/appkit/testing` and clicks from page to page, checking the page it lands on by its
`page-<view>` id. Every link or button that moves between pages gets such a test.

## Build, test, run

```sh
make build        # web → api/wwwroot, then the API; warnings are errors
make test         # Vitest, then xUnit; needs ENDGAME_TEST_DATABASE (the platform sets it)
make lint         # ESLint (zero warnings), tsc, dotnet format
make image        # the container image the platform runs
make migration name=AddSomething
```

A change is done when `make lint` and `make test` pass with zero warnings, there is a test for the
behaviour (back end and front end) and a navigation test for each new link between pages, the
screens carry their test ids, and `docs/` says what changed.

## When start-up fails

The kit stops the app with a message naming the fix — an endpoint without a name or description,
a missing environment variable, a front end built with absolute URLs, a migration that cannot
run. Read the message and apply what it says; never work around the check.
